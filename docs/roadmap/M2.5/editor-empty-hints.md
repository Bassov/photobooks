# editor-empty-hints

Tag: feature
Milestone: M2.5
Title: empty-editor card with import actions and a placement hint until the first photo is placed

## Scope

- [ ] Pasteboard empty card when `book.gallery` is empty (`src/editor/Pasteboard.tsx` has no empty state today; the only hint is `filmstrip-empty` "Add a folder or photos to build the gallery." at `src/editor/Filmstrip.tsx:195-196`). Use the `EmptyState` primitive (`ui-primitives-feedback`) in the shape `editor-chrome-states` sets: icon, "Start with your photos", one sentence, a primary "Add folder…" plus a secondary "Add photos…" that call the same handlers as the top bar (`src/editor/EditorShell.tsx` `onAddFolder` / `onAddPhotos`, `:119-150`). If `editor-chrome-states` has already placed the card, only wire the actions and the secondary button
- [ ] Placement hint: once the gallery has photos and no frame in the book has an asset, show a short non-blocking hint on the pasteboard: "Drag a photo onto a frame, or click a photo and then a frame." It disappears on the first placement (selector over the book: any frame with `assetId`; `getPlacementCountSnapshot`-style narrow subscription) and comes back only when the book is empty of placements again. Not shown in a book that already has placements
- [ ] Folder import that adds zero photos (only non-images, the `folder-skip-non-images` summary) keeps the empty card, with a secondary line "No photos found in that folder" (kit edge case `uikit/src/features/m0m1.tsx:255`)
- [ ] a11y: card actions keyboard-reachable; the hint is announced once through the polite Status, not repeated per render; the card never covers a laid-out spread's frames' hit targets in a way that blocks click-to-place (hint is `pointer-events: none` except its own buttons)
- [ ] Boundary with M8 `onboarding` (`docs/roadmap/M8/onboarding.md`: start screen explaining the flow, sample book, "helpful empty states"): this item covers only the in-editor empty card and the first-placement hint for an existing user; onboarding keeps the first-run start screen, the sample book and any multi-step tour, and must reuse this card rather than add a second editor empty state
- [ ] Spec delta `editor-shell` (new requirement "Empty editor and first placement guidance"); tests: component tests (empty → card with both actions; photos + no placements → hint; first placement → hint gone; book with placements → no hint), e2e: fresh session shows the card and its Add photos action opens the input path (`photo-file-input`), after import the hint is visible, after one drag-place (existing `e2e/drag-place.spec.ts` flow) the hint is gone
- **Done when:** (1) an e2e regression test for #43 (no pasteboard empty state or placement hint on main) passes on the branch; (2) the component tests above pass; (3) the spec delta is archived; (4) patch coverage ≥ 85%, Stryker diff ≥ 85 with zero NoCoverage, no gate weakened or newly excluded; (5) `drag-place` and pasteboard frame-budget e2e stay green
- **Perf:** the hint subscribes to one boolean (any placement) and re-renders only when it flips; the card mounts only while the gallery is empty. Gate: `drag-place-replace` scenario and the bulk-import scenario — zero LoAF.
- **Browser check:** a fresh session shows the "Start with your photos" card with Add folder… and Add photos… working; after importing, the pasteboard shows the placement hint; dragging (or click-click) the first photo into a frame removes it; reloading a book that already has placements shows no hint; a folder with only text files keeps the card with "No photos found"; no page-level H/V scroll.
